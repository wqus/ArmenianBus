# Восстановление доступа и подтверждение почты

## Результаты проверок

- **355 backend tests passed**, без пропусков, 564,46 с: полный прогон текущей
  версии в отдельном PostgreSQL 17. Два прежних deprecation-предупреждения
  Starlette/AnyIO; ошибок нет.
- **67 frontend unit tests passed**; TypeScript, production build, ESLint,
  Prettier, Ruff и синхронизация справочников городов/салонов пройдены.
- **14 целевых backend-тестов passed** в изолированной PostgreSQL: восемь
  интеграционных сценариев и шесть проверок токенов/конфигурации.
- Пройдены **150 различных браузерных сценариев** Chrome desktop/mobile,
  включая 12 новых сценариев восстановления/подтверждения. В полном прогоне
  прошли 149; один прежний тест возврата с оплаты остановился до запуска
  приложения: Chrome не загрузил `App.tsx` с `net::ERR_NO_BUFFER_SPACE`.
  Трасса проверена; этот сценарий повторён отдельно два раза, оба успешно,
  без изменений кода и без увеличения таймаутов.
- Ранее в рамках этой реализации пройдены три проверки собранной HTTPS-среды:
  redirect, SPA и Secure-cookie login/refresh/logout. Отдельный smoke-проект
  после проверки удалён.

## Проверенный контракт

- Запрос восстановления даёт одинаковый ответ для доступного и неизвестного
  аккаунта; выключенная почта сообщает о недоступности, а не об отправленном письме.
- Ссылки одноразовые, имеют срок действия и отдельное назначение. Проверены
  подмена, истечение, повтор, блокировка пользователя и ротация серверного ключа.
- После сброса отзываются старые access/refresh-сессии, включая прежние JWT без
  поля версии. Автоматический вход не выполняется. Старый пароль не подходит,
  новый подходит; опоздавший вход со старым хешем отклоняется.
- При двух конкурентных сбросах успешен один. Новые запросы не отменяют старую
  действующую ссылку; есть ограничения частоты по аккаунту и через Redis.
- GET не расходует ссылку. Подтверждение требует явного POST; статус обновляется
  в профиле другой открытой вкладки. Сброс завершает браузерную сессию и удаляет cookie.
- В приватной очереди хранится хеш ссылки; письмо создаётся в памяти worker.
  FakeSender проверяет повторы SMTP, отсутствие секретов в ошибках, исключительное
  получение lease и отказ от отправки протухшего действия. Уведомление о смене
  пароля ставится в очередь также во время отключённой доставки.
- Браузер удаляет секрет из адресной строки, не пишет его в storage/DOM. Проверены
  повторное нажатие, новая ссылка в той же вкладке, потеря ответа и уход со страницы.

## Ограничения

Данные синтетические. Автоматические проверки не отправляют настоящие письма
или платежи. В отдельном проекте api-e2e используется `smtp.invalid` без SMTP-worker:
тест получает только собственную ссылку из проверенной БД `armeniabus_test`.
Реальную доставку новых шаблонов через целевой SMTP ещё нужно принять отдельно.
VPS не обновлялся. Мобильные проверки используют эмуляцию Chrome;
Firefox/WebKit и реальные устройства в этом прогоне не проверялись.
