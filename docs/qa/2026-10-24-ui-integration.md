# Проверка интерфейса armatrans — 24 октября 2026

Проверены главная и поиск, выбор места, бронирование, оплата и результат,
история пассажира, кабинеты перевозчика и администратора. База оформления —
`a5fad31` в `codex/ui-ux-concepts`; исправления проверки сохранены в этой ветке.
Проверка локальная, VPS и публичный сайт не обновлялись.

## Найдено и исправлено

1. `npm audit` обнаружил пять затронутых пакетов инструментов разработки и
   сборки: Vite, Vitest, `@vitest/mocker`, `source-map-js`, Zod. Зафиксированы
   Vite **8.3.5** и Vitest **5.0.5**; lock-файл содержит `@vitest/mocker` 5.0.5,
   `source-map-js` 1.2.2 и Zod 4.6.7. Основные версии не менялись. После обновления
   локальный аудит и `npm ci` внутри сборки Docker показывают **0 известных
   уязвимостей**. В frontend-job CI добавлен `npm audit --audit-level=high`.
2. Повторный HTTPS smoke воспроизвёл пересечение подсетей Docker: автоматически
   выделенная сеть backend могла занять /16, включающий фиксированный /24 edge.
   Smoke-runner теперь проверяет существующие Docker-подсети и задаёт две
   непересекающиеся /24 через временный Compose override. Этот override сохраняется
   при учебном обновлении/откате; первый запуск пилота использует тот же механизм.
   При исчерпании пула проверка завершается ошибкой. Рабочие Compose-файлы,
   настройки VPS и чужие сети не изменяются. Временный override удаляется после
   очистки выделенного тестового проекта.

Бизнес-логика приложения, миграции и HTTP-контракты этой проверкой не менялись.

доставки, экранирование аудита и восстановление после ошибки загрузки страницы.

Для настоящего API использовался только Compose project `armeniabus-auth-e2e`
с БД `armeniabus_test`. Платежи и почтовая доставка не включались. HTTPS smoke
запускает отдельный проект со случайным именем, внутренним тестовым CA и
синтетическими аккаунтами; проверяет редирект, SPA reload, CSP/HSTS, неизменяемые
assets, закрытые служебные URL и Secure/HttpOnly-cookie login/refresh/logout.

## Границы проверки

Firefox и WebKit в этом локальном прогоне не подтверждены: загрузка браузеров
через Playwright остановилась на повторных тайм-аутах CDN при скачивании Firefox.
Матрица этих движков остаётся в CI. Ручной аудит со screen reader также не
выполнялся; успешный axe-прогон не заменяет его.

Реальные SMTP-письма, платёж/возврат через ЮKassa, внешний webhook и серверное
окружение этой проверкой не затрагивались. Локальные результаты не являются
приёмкой внешних интеграций или доказательством готовности публичного production.

## Воспроизведение

Для frontend: `npm run format:check`, `npm run lint`, `npm test`, `npm run build`,
`npm audit --audit-level=high`. Полный прогон: `npx playwright test --workers=2`
с `PLAYWRIGHT_CHANNEL=chrome`, `RUN_AUTH_E2E=1` и
`API_PROXY_TARGET=http://127.0.0.1:8001` после подготовки изолированного API по
[browser-auth.md](../browser-auth.md).

Собранная версия: `npx playwright test -c playwright.browsers.config.ts
--project=chromium-qa --workers=2`. Перед запуском освободить тестовый порт 5174.
HTTPS и учебный выпуск: `python scripts/deployment_smoke.py --release-drill`.
`--skip-build` допустим только при наличии образов, собранных из проверяемого кода.

Карточка одной из устранённых проблем инструментария:
[Vitest: manual mock registration](https://github.com/vitest-dev/vitest/security/advisories/GHSA-qxg6-89mg-rqv8).
Полный актуальный состав и результат аудита воспроизводятся из `package-lock.json`.
