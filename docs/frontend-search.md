# Публичный поиск в браузере — F3

Главная содержит форму направления/даты, а `/search` показывает реальные данные `GET /api/v1/routes/search`. Вход не требуется. В запросе нет Bearer и cookies; список городов, перевозчиков, цены и наличие мест не подменяются демонстрационными данными.

## Поведение

- Полные названия городов вводятся свободно, без фиксированного списка. Пробелы по краям удаляются. API сопоставляет названия без учёта регистра; алиасов и транслитерации нет. Кнопка меняет города местами.
- Дата и время явно показаны в UTC, как в [контракте B5](search-and-availability.md). Часовой пояс устройства не меняет день поиска. Прошедший день допускается и возвращает пустую выдачу.
- Параметры `origin`, `destination`, `date`, `offset` сохраняются в URL: поддерживаются обновление, ссылка и история браузера. Изменение направления/даты сбрасывает страницу. Невалидная дата, пустой город, повтор параметра или некорректный offset не отправляются API.
- Поиск запускается при отправке формы. Изменение запроса отменяет прежний fetch; поздний ответ другого направления не заменяет текущую выдачу. Повтор той же формы и кнопка обновления запрашивают свежие сведения. Автоматического polling нет.
- Карточки показывают направление, перевозчика, UTC-отправление, точную цену RUB за пассажира и количество свободных мест. Цена форматируется из десятичной строки через BigInt, без округления float. Название автобуса, вместимость и страны раскрываются через native details.
- Полностью занятые рейсы остаются в выдаче с отметкой «Свободных мест нет». Поиск не создаёт удержание. Выбор конкретного места и отдельная страница рейса — F4, создание брони — F5.
- Загрузка, пустой результат, ошибка сети/API, некорректный ответ и повтор запроса имеют отдельные состояния. При обновлении старые цены и места скрыты до нового ответа. Технические сообщения backend не выводятся посетителю.

## Пагинация и проверка контракта

На странице до 20 рейсов, запрос содержит `limit=21`. Двадцать первый результат только определяет наличие следующей страницы; следующий `offset` увеличивается на 20. Общее количество и количество страниц не выдумываются. Максимальный offset — 10000, как в API. Если результаты между запросами исчезли, пустая следующая страница сохраняет переход назад. При достижении предела предлагается уточнить поиск.

Сортировка выполняется backend по времени и UUID. Это живая выдача, а не неизменяемый snapshot: изменения расписания могут сдвигать записи между страницами. Реальные данные перед отображением проверяются: структура страницы, цена/валюта, дата со смещением, страны, вместимость, границы свободных мест. Backend остаётся источником прав доступа, статусов и доступности.

## Проверки

Unit-проверки покрывают Unicode и спецсимволы URL, календарные границы, недопустимые параметры, Decimal, UTC-переход через полночь, lookahead и некорректные ответы. Браузерные сценарии проверяют форму/перестановку, историю и reload, переходы страниц, загрузку/ошибки/повтор, sold-out, доступность axe, адаптивность и поздние ответы.

`e2e/search-live.spec.ts` дополнительно создаёт администратора через CLI в фиксированном Compose project `armeniabus-auth-e2e`, проверяя имя БД `armeniabus_test`. Через настоящий API создаёт перевозчика/автобус/черновик, публикует рейс, удерживает и освобождает единственное место. Поиск в браузере проверяется без авторизации. UTC-дата отличается от календарной даты исходного смещения `+03:00`. Синтетические данные существуют только в отдельном проекте и удаляются вместе с ним.

Live-сценарии включаются существующим `RUN_AUTH_E2E=1`, требуют `API_PROXY_TARGET=http://127.0.0.1:8001` и запускаются той же командой `npm run test:e2e`. Подготовка и обязательная очистка — [инструкция browser-auth](browser-auth.md). CI запускает новые файлы автоматически. Backend и схема БД в F3 не изменялись.
