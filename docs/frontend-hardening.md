# F10 — устойчивость и доступность интерфейса

Этап охватывает адаптивность, базовую доступность, загрузку, пустые/ошибочные состояния и браузерную проверку. Реализованные изменения проверяются отдельно от готовности публичного production-развёртывания.

## Поведение

- Кнопка сохраняет своё название во время запроса, получает `aria-busy` и блокируется; индикатор скрыт от accessibility tree. Загрузка страниц и данных показывает текстовый `status` и декоративные skeleton-полосы. Анимации отключаются при `prefers-reduced-motion`.
- При первом открытии страницы фокус не перехватывается: первый Tab достигает skip-link. При переходе между путями внутри приложения фокус переносится в основной контент. Выбор места доступен с клавиатуры, занятые места отключены.
- При событии offline появляется сообщение о возможной неактуальности данных и необходимости проверить результат перед повтором операции. `navigator.onLine` — только подсказка браузера, не проверка доступности API. Сообщение не повторяет мутации; серверные ошибки продолжают обрабатываться отдельно.
- Без Web Locks/BroadcastChannel либо при запрете создания канала приложение объясняет недоступность входа и сохраняет публичный поиск. Для сессии нужен поддерживаемый браузер и HTTPS (либо localhost). Без JavaScript виден `noscript` с объяснением.
- Страницы администрирования и управления автобусами/рейсами/бронями перевозчика загружаются отдельными модулями. Сбой загрузки модуля показывает общий экран ошибки с ручным обновлением текущего адреса. Автоматического цикла перезагрузок нет.
- При смене пути старая форма размонтируется, даже если следующий модуль ещё загружается. Поздний ответ на создание автобуса не перенаправляет пользователя обратно после перехода в другой раздел. Регрессионный сценарий задерживает одновременно API-ответ и модуль назначения.

## Границы запросов и сессии

`Session.request` запоминает поколение сессии **до** обновления access token. Если refresh обнаруживает другого пользователя, исходная операция завершается `AbortError` до отправки с новым токеном. После 401 чтение также не повторяется под другой учётной записью. Обычный refresh того же пользователя продолжает работать; мутации автоматически не повторяются.

API-клиент отклоняет пути, выходящие из `/api/v1/` после нормализации, до отправки запроса. Таймаут действует также при чтении тела ответа; отмена вызывающей стороной сохраняет `AbortError`, а таймаут отображается как `REQUEST_TIMEOUT`. Runtime-проверки ответов предметных API сохраняются.

## Проверки и воспроизведение

Основной набор Playwright проверяет desktop и mobile emulation. `e2e/hardening.spec.ts` дополнительно покрывает управляемую задержку, ошибку и пустую выдачу, reduced-motion, ограниченные session API, клавиатуру, offline/online без записей, ширины 320/768/1024/1440, длинные русские/армянские значения, увеличение текста, отказ lazy-модуля и выключенный JavaScript. Axe проверяет загрузку, места и форму перевозчика. Это автоматические проверки выбранных экранов, не полный аудит WCAG или screen reader.

Отдельная конфигурация `playwright.browsers.config.ts` запускает те же семь сценариев на **production bundle** в Chromium, Firefox и WebKit. API-ответы в этом наборе синтетические; Vite preview используется только для QA. Команды из `frontend`:

```powershell
npm run build
npx playwright install chromium firefox webkit
npm run test:browsers
```

При доступном установленном Edge можно проверить только Chromium-проект:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:browsers -- --project=chromium-qa --workers=1
Remove-Item Env:PLAYWRIGHT_CHANNEL
```

Порт 5174 должен быть свободен: production-проверка специально не переиспользует запущенный dev server. Основной набор с настоящим API запускается отдельно, по [browser-auth.md](browser-auth.md). Изолированный Compose project не использует рабочую БД. Снимки/trace сохраняются в игнорируемом `frontend/test-results/`; production-матрица — в подкаталоге `browsers`.

В CI добавлены установка трёх движков и `npm run test:browsers` после основного E2E. Локальная установка Firefox и WebKit 27 сентября 2026 года завершилась таймаутами всех предложенных официальных CDN-зеркал. Эти движки остаются непроверенными до успешной установки/прогона. Наличие CI-конфигурации не означает успешного удалённого запуска. Проверка на настоящих iOS/Safari и с screen reader также остаётся отдельной работой.

## Результат локальной проверки

27 сентября 2026 года прошли 50 unit-тестов, TypeScript/production build, ESLint и Prettier. Отдельные семь проверок production bundle прошли в установленном Microsoft Edge. Снимки загрузки desktop/mobile и формы с увеличенным текстом просмотрены; на проверенных экранах axe не обнаружил нарушений.

Итоговый полный повтор на исправленном коде: **112 из 112 E2E** desktop/mobile Edge, включая 10 сценариев с настоящими API/PostgreSQL в отдельном Compose project. Удалённый CI не запускался. Firefox/WebKit не входят в эти результаты.

В предварительной проверке исправлен перехват фокуса при первом открытии, а в полной регрессии — гонка позднего ответа при загрузке следующего раздела. Backend и миграции не изменялись; схема остаётся 0010. Настоящий платёжный провайдер и SMTP не использовались.
